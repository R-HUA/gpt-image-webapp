# 后端托管模式

本分支新增 Node 后端，前端构建后由后端直接托管，不需要 nginx。

## 启动

```bash
npm install
npm run build
npm run server
```

默认监听 `http://0.0.0.0:4173`。可用环境变量覆盖：

```bash
GIP_HOST=0.0.0.0
GIP_PORT=4173
GIP_DATA_DIR=./server-data
GIP_OUTPUT_DIR=./server-data/output
GIP_THUMBNAIL_DIR=./server-data/thumbnails
GIP_BATCH_UPLOAD_DIR=./server-data/batch-uploads
```

默认管理员写死在 `server/config.js`：

- 用户名：`admin`
- 密码：`admin123456`

首次初始化时会把默认管理员密码写入数据文件；已有 `server-data/db.json` 后不会在每次启动时重置管理员密码。管理员登录后打开“设置”，进入“管理员”子菜单，配置上游服务商 Base URL、上游服务商密钥、模型、总体并发数、服务器图片目录和后端访问令牌。

## 数据方案

当前实现使用 `server-data/db.json` 保存用户、管理设置、后端访问令牌和生成结果元数据。图片原图保存到输出目录，缩略图保存到独立缩略图目录，批量上传的原始输入图保存到批量上传目录。

这个方案适合单机部署，免 native 数据库依赖。后续如果需要多进程部署、审计查询或数十万级结果记录，建议迁移到 SQLite 或 PostgreSQL。

## 行为说明

- 浏览器只请求同源后端 `/api/*`，不会直接请求图片服务商。
- 用户必须登录后才能提交生成请求，不提供注册入口。
- 普通用户只能查看自己的图库结果。
- 管理员默认查看自己的图库，可切换全部或某个用户；管理员删除结果后普通用户不可见，管理员仍能看到遮罩标记。
- 管理员可以编辑普通用户显示名、重置普通用户密码、启用/禁用或删除普通用户。
- 生成结果先写入服务器输出目录，再返回给前端；前端仍保存当前浏览器自己的任务历史。
- 后端队列默认并发为 2，请求执行前会随机等待 50 到 349 毫秒。
- 后端会记录登录、用户管理、设置变更、后端访问令牌管理、任务创建/取消、图库删除等审计日志，管理员可在设置的管理员子菜单查看。
- 服务器图片目录批量仅管理员可从 UI 或 API 触发，后端会校验传入目录必须等于管理员保存的目录，且只读取该目录下文件，不递归子目录。
- 批量上传的本地输入原图会保存到批量上传目录，管理员可在设置的管理员子菜单查看并删除这些原图备份。
- 后端向 stdout 输出接近 log4j 的单行日志，Docker 中可直接用 `docker compose logs -f` 排查任务入队、上游请求、落盘、缩略图和错误堆栈；上游失败会带 HTTP 状态、接口路径、模型、请求类型和响应摘要。
- 图库接口支持分页，默认每页 40 条，最大每页 100 条。
- 缩略图由后端使用 `sharp` 生成压缩 WebP 文件，独立保存在缩略图目录。
